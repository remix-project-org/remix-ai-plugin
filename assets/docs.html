Overview

Remix Solidity is an MCP server for smart-contract work. It compiles Solidity with the Remix compiler, encodes contract calls, reads the state of deployed contracts, and simulates deployments and function calls on major EVM chains. A simulation tells you whether a transaction would succeed, what it would cost in gas, what it would return or why it would revert, and gives a plain-language review of what it does.

This server only simulates. It has no tool that signs, sends or broadcasts a transaction, it never asks for or holds private keys, seed phrases or funds, and nothing is written on-chain. To deploy or call a contract for real, use your own wallet or deployment tooling. No account or sign-in is needed.

Connect

The server speaks MCP over Streamable HTTP at:

{{BASE_URL}}/mcp
  • Claude (custom connector): in Claude's connector settings, add a custom connector and enter the URL above.
  • Claude Code plugin: install the Remix Solidity plugin, which points at the same URL and adds two skills, simulate-deployment and simulate-call.
  • ChatGPT (developer mode): add the URL above as an MCP connector.

Tools

All four tools are read-only. Tool failures come back as a result with success: false and an error message, not as protocol errors.

compile_solidity

Compiles one or more Solidity files with the Remix compiler and returns the ABI, bytecode, and any errors or warnings. Imports that are not in the request (for example @openzeppelin/contracts/...) are fetched automatically.

ParameterDescription
sources (required)Map of filename to { "content": "..." } for each Solidity file
versionCompiler version, for example v0.8.28+commit.7893614a. Defaults to 0.8.28.
settingssolc settings such as the optimizer and output selection

encode_call

ABI-encodes a function call, or a deployment with constructor arguments, so you can inspect the calldata. It runs on the server only and does not contact a chain. To see what the data would do on-chain, use simulate, which encodes for you.

ParameterDescription
abi (required)JSON ABI (array or string), the compiled contract output, or human-readable signatures such as function transfer(address to, uint256 amount)
functionNameFunction name or full signature. Omit when encoding a deployment.
argsArguments in ABI order. Pass uint and int values as decimal strings, addresses as 0x strings, arrays and tuples as JSON arrays.
bytecodeCreation bytecode. When set, encodes a deployment with args as constructor arguments.

read_contract

Calls a view or pure function on a deployed contract (eth_call) and returns the decoded result. Calling a state-changing function this way only simulates it.

ParameterDescription
address (required)Deployed contract address
chainId (required)EVM chain ID, see Chains
abi (required)Contract ABI, as for encode_call
functionName (required)Function name or full signature, for example balanceOf
argsArguments in ABI order
fromCaller address (msg.sender) for the call

simulate

Dry-runs a deployment or a function call against the chain's latest state and reports what would happen. Nothing is signed, sent or stored. The server runs eth_call and eth_estimateGas on an RPC node and builds a clear-signing review in parallel.

ParameterDescription
chainId (required)EVM chain ID, see Chains
toContract address for a call. Omit for a deployment.
abiContract ABI. Required with functionName or bytecode. With pre-encoded data it is only used to show the decoded call.
functionNameFunction to call, by name or full signature. Requires to and abi.
argsFunction or constructor arguments in ABI order
bytecodeCreation bytecode for a deployment (evm.bytecode.object from compile_solidity). Requires abi.
dataPre-encoded calldata, instead of abi with functionName or bytecode
valueETH to send, as a hex string such as 0x0 or a decimal string in wei
fromCaller to simulate as. Without it the zero address is used, so balance and permission checks may fail for the wrong reason.

Example request:

{
  "to": "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2",
  "abi": ["function name() view returns (string)"],
  "functionName": "name",
  "chainId": 1
}

Example response (trimmed):

{
  "simulated": true,
  "success": true,
  "chainId": 1,
  "gasEstimate": "24513",
  "returns": {
    "signature": "function name() view returns (string)",
    "outputs": [{ "name": "", "type": "string", "value": "Wrapped Ether" }]
  },
  "review": { "intent": "Call name on WETH9", "source": "verified", "warnings": [] },
  "note": "Simulation only: nothing was signed or sent, ..."
}

Prompts

Clients that support MCP prompts show these as ready-made workflows.

PromptArgumentsWhat it does
simulate-deploymentsource, filename, chain_idCompiles a contract, then simulates deploying it
simulate-calladdress, abi, function_call, chain_id, from, valueReads a view function, or simulates a state-changing call on a deployed contract

When no chain is named, workflows default to Sepolia (chain ID 11155111).

Example requests to Claude

  • "Compile this contract and simulate deploying it to Sepolia." (paste your Solidity source)
  • "What is the totalSupply of the USDC contract at 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48 on Ethereum mainnet?"
  • "Simulate transfer(0x…, 1000) on this contract on Base from this address and tell me if it would revert."
  • "What would approving unlimited USDC to this spender do? Simulate it and show the warnings."

Reading a simulation result

FieldMeaning
successtrue if the call or deployment would succeed, false if it would revert
gasEstimateEstimated gas, when the simulation succeeds
returnsDecoded return value of a call, when the ABI describes the function
deployedCodeBytesSize of the runtime code a deployment would create
revertWhen it fails: message, the revert reason if there is one, a decoded customError when the ABI defines it, and the raw data
decodedThe call or constructor as the server understood it, with decoded arguments
reviewClear-signing review: intent (one-line summary), source, contractName and warnings

Where a review comes from

review.sourceMeaning
erc7730Matched a descriptor in the ERC-7730 clear-signing registry
verifiedBuilt from the contract's verified source on Sourcify
assistantBuilt only from the ABI supplied in the request, so it is as trustworthy as that ABI
noneNo contract call to describe, for example a plain ETH transfer

Warnings have a level of danger or caution. They flag risks such as an unlimited token approval, approving all NFTs in a collection, a change of contract owner or implementation, or a call to an address with no contract.

Limits and behaviour

  • A simulation is a prediction. It runs against the latest block. A real transaction can behave differently if chain state changes first.
  • No state diff. You get the return value or revert reason and the gas estimate, not balance changes, token transfers or event logs.
  • Default sender. Without from, the zero address is the caller. Pass from when the result depends on who calls.
  • Public RPC nodes. Requests go to public nodes that can rate-limit or fail. A request that gets no answer within 20 seconds fails.
  • Compilation. Compiles time out after 60 seconds. The default compiler is 0.8.28.
  • Imports. Files not included in the request are fetched only over HTTPS from unpkg.com, cdn.jsdelivr.net and raw.githubusercontent.com (including GitHub file links).
  • Request size. Requests larger than 5 MB are refused.
  • Rate limiting. The server may limit requests per client. Over the limit it answers HTTP 429 with a Retry-After header.

REST API
