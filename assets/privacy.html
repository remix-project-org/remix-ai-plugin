Remix Solidity plugin privacy policy

Overview

This policy explains what data the Remix Solidity plugin and its server at ai-plugin.remixlabs.dev send, store and share. The server is run by Remix Labs. Short version: the server only simulates, it has no accounts, and it keeps no database of what you send.

It covers the Claude plugin and the MCP server it connects to. It does not cover Claude itself, which is governed by Anthropic's own terms and privacy policy.

What we collect

When Claude calls a tool, the plugin sends that tool's inputs to our server. Depending on the tool, they can include:

  • Solidity source code and compiler settings
  • contract ABIs, function names and arguments
  • contract and caller addresses, call data, ETH amounts and chain IDs

We also record minimal usage analytics: the tool name, the client name, the outcome (success or failure) and the chain ID. Analytics never include source code, addresses, call data or amounts.

No account or sign-in is needed, and the server does not require authentication. We never ask for or receive private keys, seed phrases or funds.

We have disabled access logging on our server and do not store IP addresses. Our hosting provider and network proxy (Cloudflare) process IP addresses to deliver requests and may keep short-term technical logs under their own policies.

Who receives data to answer a request

To answer a request, the server passes some of the data above to these services:

ServiceWhat it receives
Public blockchain RPC nodes for the chosen chainContract and caller addresses, call data, values and the chain ID, for reads and simulations, plus ENS name lookups
Sourcify (sourcify.dev)Contract address and chain ID, to fetch verified source code and ABIs
ERC-7730 clear-signing registry (raw.githubusercontent.com)Requests for the registry index and the descriptor files of the contracts involved
npm CDN (unpkg.com or jsDelivr) and GitHubThe path of an imported Solidity file, such as an OpenZeppelin contract, that was not included in your request

Blockchain data is public by design. Addresses and call data sent to an RPC node for a simulation may be visible to that node's operator. We do not sell your data or use it for advertising.

How long we keep it

The server does not store request data in a database or on disk. It keeps short-lived in-memory caches only: fetched import files, recently encoded calls, and public contract metadata for up to 6 hours. These caches are cleared when the server restarts.

Usage analytics (tool name, client name, outcome and chain ID) contain no personal content. They are kept until we delete them; there is no fixed retention period.

What we do not do, and your choices

  • The plugin never signs, sends or broadcasts a transaction, and nothing is written on-chain. To deploy or call a contract for real, use your own wallet or deployment tooling.
  • We do not read Claude's memory, chat history or uploaded files. We only receive the inputs Claude passes to a tool.
  • We do not use your inputs to build user profiles.

Simulations are public-chain queries and cannot be undone once sent to an RPC node, so avoid including secrets in Solidity source or call arguments. To stop all data flowing to the server, uninstall the plugin.

Security, children and changes

The server is served over HTTPS. The service is not directed at children under 16. We will post changes to this policy at this address and update the effective date below.
